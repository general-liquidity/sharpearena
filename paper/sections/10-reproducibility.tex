\section{Reproducibility statement}\label{sec:repro}

The Cargo workspace has two members, \texttt{sharpearena} and \texttt{sharpearena-wasm}; the separately built and explicitly excluded \texttt{sharpearena-py} crate supplies the PyPI package. The surfaces are published under the MIT and Apache-2.0 licenses, with a pinned toolchain and a lockfile, and depend on published SharpeBench engine crates rather than a vendored copy. The core forbids unsafe code. The determinism claims are enforced rather than asserted: exact canonical JSON fixtures precede the committed FNV-1a hashes of generated scenarios and the matching engine's fill tape; the WebAssembly crate asserts byte-identity with the native engine for stepping and scenario generation; the scenario fixtures execute on \texttt{wasm32} under Node and against the committed \texttt{.wasm}; and the npm suite performs the replay-and-decision-tamper check of \cref{sec:replay}. The cross-wrapper \texttt{SPEC\_HASH} adds a refusal boundary for a mismatched engine and wrapper. The contract artifacts, schemas, conformance fixtures and governance document are committed beside the code they govern, and a conformance test exercises the fixtures.

Continuous integration covers the Rust surface with formatting, lints as errors, tests, a WASM target build and a \texttt{wasm32} execution of the scenario goldens, plus dependency auditing, npm, the Python wheel and the evidence manifest. Two jobs test consumer usability rather than source-tree identity: one packs the npm tarball and installs it offline into a fresh project before calling a real export; the other builds the wheel, installs it into a fresh virtual environment outside the checkout, imports it and steps one bar. The latter also asserts that \texttt{py.typed} and the native-extension stub ship. The evidence validator runs on every push to main and every pull request and binds the commit it runs on rather than the commits behind it (\cref{app:commands}).

Every number in \cref{sec:validation,sec:findings} is produced by a committed script under \texttt{paper/src/} from fixed seeds, writing JSON evidence to \texttt{paper/evidence/} and figures to \texttt{paper/figures/}; the commands are listed in \cref{app:commands}. The scripts call the package's public Python API. The current manifest binds the checked artifact set to the present source snapshot, but it cannot reconstruct a runtime version that an older evidence file did not record. Exact clean-room regeneration therefore requires the original source revision and locked dependencies; where those are absent, the claim is integrity of the committed artifact and producer, not demonstrated regeneration from the current package.

The model-agent, generated-strategy, prospective-forecast and paper-only forward paths of \cref{sec:agentic} are product surfaces, not sources for any admitted number in this manuscript. Nothing has been promoted through the path of \cref{sec:trace-promotion} into the F1--F8 evidence set. The archived prospective pilot is a separately labeled engineering trace, not a finding; retaining its raw bytes does not admit its obsolete checkpoint scores. Deterministic tests use injected model transports and fixed decisions; continuous-batched inference, model-server scheduling and live provider data are outside the golden-hash claim. A future current-model field must bind the exact model artifact, inference runtime, prompt and scaffold, decoding configuration, sampling seed, raw completion, semantic-validation outcome and fault class. Environment bytes and replay can remain fixed while agent outputs vary, and the evidence schema preserves that distinction.

The products compose through files rather than a mutual dependency. SharpeArena writes and validates complete append-only cell journals and prospective forecast ledgers; SharpeBench independently reads those artifacts for field-level evaluation. The executable cross-product tutorial fixes a synthetic two-producer artifact and checks the resulting report. The two Lean projects model complementary invariants: Arena's deadline, revision, binding and fixed-point Brier rules, and Bench's common-support intersection, Holm monotonicity and bound, finite-bootstrap correction and trading-rank isolation. These proofs do not extract or verify the Python and Rust implementations; executable conformance tests connect the abstract models to code.

No large language model is a component of the environment, the contract or any admitted result. The environment has no judge. The superseded engineering pilot is retained outside the paper's empirical conclusions. We used language models to draft and edit prose, and we checked every bibliography entry against its source.

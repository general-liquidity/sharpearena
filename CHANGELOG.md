# Changelog

All notable changes to SharpeArena are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/). One workspace
version covers the Rust crates, the npm package and the PyPI package; each
section is one `v*` tag and links the commits it was built from. The wire
contract has stayed at `CONTRACT_VERSION` 1.0 throughout.

[Unreleased]: https://github.com/general-liquidity/sharpearena/compare/v0.27.0...HEAD

## [Unreleased]

## [0.27.0] - 2026-09-12

### Fixed

- release: the committed wasm bundle is rebuilt for 0.26.0. Every other version
  the release checks is a literal in a metadata file that the version bump
  rewrites; the one inside the wasm binary comes from `CARGO_PKG_VERSION` at
  compile time, so the bump left the committed bundle reporting 0.25.0 against a
  0.26.0 tag. This release publishes the committed bundle rather than a rebuild,
  by design, so the npm job refused it after crates.io and PyPI had already
  published. v0.26.0 is therefore on crates.io and PyPI and not on npm.

### Changed

- release: the release now rebuilds the committed wasm bundle after the version
  bump, inside the release tree, and folds it into the version-bump commit. The
  bundle carries its own version compiled in from `CARGO_PKG_VERSION`, which the
  bump cannot rewrite the way it rewrites a literal in a manifest, so cutting
  v0.26.0 tagged a tree whose bundle still said 0.25.0 and the npm job refused it
  after crates.io and PyPI had published. A pre-tag check cannot close this,
  because before the bump there is no version for the bundle to name; the rebuild
  has to happen after it. `wasm-pack` is now required to cut a release, and the
  release refuses rather than tagging a bundle it could not rebuild.

## [0.26.0] - 2026-09-12

### Breaking

- Rust `train_test_split` returns `Result<(ScenarioSpec, ScenarioSpec), SplitError>` instead of an unconditional pair. The train/test disjointness the whole overfitting measurement rests on was carried by two `debug_assert!` statements, and `[profile.release]` enables no debug assertions, so neither existed in the published crate, the maturin wheel or the wasm bundle: an unbounded train interval (`num_levels == 0`, which `level_seed` reads as Procgen's unlimited) produced a held-out family lying entirely inside the train band, and `start_level + num_levels + gap` wrapped rather than panicking, which could land the test band below the train band. Both are now typed refusals in every profile, `SplitError::UnboundedTrain` and `SplitError::BandOverflow` over `checked_add`, following the crate's existing convention for input that cannot produce a valid result (`SealedSalt::new`) and joining the one `[CODE]` message register `tests/error_style.rs` applies to every `Display` error the crate defines. `train_test_split` has no pyo3 and no wasm export, so the break reaches direct Rust callers only; in-repository callers are the crate's own tests. Valid inputs return the same two specs as before.
- Rust `mandate_breach` returns `Result<f64, MandateError>` instead of an unconditional penalty. Every breach source folded in with `f64::max`, which discards a NaN operand, and every guard was a `>` comparison, which is false for NaN, so a single non-finite weight or return scored a clean `0.0` on all four sources at once: the long-only rule, the market-neutral and pairs-convergence rule, the inventory cap and the drawdown cap. The reward layer turns the penalty into `1 - breach`, so a NaN book collected full credit. `MandateError::NonFiniteReturn`, `NonFiniteWeight`, `InvalidDrawdownCap` and `InvalidInventoryCap` each name the offending position and value, following the convention `SealedSalt::new` and `train_test_split` already set and joining the `[CODE]` register `tests/error_style.rs` enforces. The cap variants are new refusals of their own: a `max_drawdown` outside `(0, 1]` or a non-positive `max_inventory` was previously consumed by `cap.max(EPS)`. The pyo3 `mandate_breach` re-raises as `InvalidArgument`, so Python `sharpearena.mandate.mandate_breach` and `mandate_reward` now raise for those inputs; there is no wasm or npm export of this function. Valid inputs return the same number as before.
- Rust `exec_noise::perturb` (re-exported as `perturb_action`) returns `Result<Vec<f64>, ExecNoiseError>` instead of an unconditional action, and `ExecNoise::validate` is public. These are reportable benchmark-integrity knobs, and all three out-of-range shapes failed quietly: a negative knob took the "no knobs configured" fast path, so a run disclosing `delay_prob = -0.1` was in fact noise-free; `delay_prob > 1` made `rng.next_unit() < delay_prob` always true, so the agent's own decisions never reached the market; and a NaN passed every guard, producing a NaN action that `np.clip` propagated into `env.step`. `delay_prob` must now be finite in `[0, 1]` and `slippage_bps` finite and non-negative, checked before any draw is taken, so a refused config cannot consume the step's stream. Every surface that accepts a knob validates: the pyo3 `perturb_action` raises `InvalidArgument` (it was the one boundary in that file passing its arguments through unchecked, unlike `score_run` and `validate_impact_exponent` beside it), `ExecutionNoiseWrapper.__init__` raises `ValueError` via the new `sharpearena.execution_noise.validate_execution_noise`, and `ExecutionNoiseConfig` gained the `__post_init__` its sibling `PreprocessingConfig` already had, so `ExecutionNoiseConfig.enabled` can no longer report a NaN as live through `nan != 0.0`. There is no wasm or npm export of either knob. Valid knobs keep their bits.
- Python `sharpearena.generalization.evaluate_seeds` records `deflated_sharpe` as the `unavailable_scoring_kernel_error: ...` string where it previously wrote `0.0`. It bypassed `score_run` below two pooled observations and published the kernel's no-skill floor as a score, so an empty `seeds` list or a suite whose episodes all end before their second bar produced a scored generalization row for an evaluation with no evidence in it, and `kernel_score_difference` would difference that zero against a real score. The kernel is now always asked and its typed refusal recorded through the path the rest of the module already uses, which also makes `generalization_gap`'s `gap_deflated_sharpe` and `cross_regime_transfer`'s `transfer_gap_deflated_sharpe` unavailable rather than a difference against a floor. Callers that did arithmetic on the field without `is_kernel_score_unavailable` must check it, as they already had to for every other withheld score. `passed_k_rate` and `mean_return` are plain tallies, not kernel scores, and are unchanged.
- Python `sharpearena.verifiers_env.mandate_reward` raises the new `sharpearena.mandate.MandateError` for a scenario carrying a mandate that does not validate, where it previously returned the vacuous `1.0`. An unparseable payload, an unrecognized style, a `max_drawdown` outside `(0, 1]` and a non-positive `max_inventory` all read as "there is no mandate", which is full credit, so the malformed input was the best-scoring one. Absence and malformation are now distinct: a scenario with no mandate keeps its `1.0`. The same conflation in the rollout's `setup_state` is closed the same way, so a dataset row carrying a mandate that does not validate is refused rather than silently replaced by the seed-derived draw; a row with no mandate still falls back to it. `require_mandate` is exported beside `validate_mandate`, which is unchanged and still returns a bool.
- npm: `@general-liquidity/sharpearena` declares an `exports` map, so **every deep subpath import is refused** with Node's `ERR_PACKAGE_PATH_NOT_EXPORTED`. `require("@general-liquidity/sharpearena/pkg/sharpearena.js")` returned the raw wasm kernel with no spec-hash handshake at all: the refuse-on-mismatch check lives in the wrapper's module body, which the deep path never executes, so a bundle and a wrapper from different tape-semantics revisions produced numbers instead of a named error. The package entry point (`.`) and `./package.json` are the only resolvable specifiers. Consumers reaching into `pkg/` must call the wrapper instead; `generate_scenario`, the one export that was reachable only through the deep path, is now wrapped as `generateScenario`. Resolvers that ignore `exports` (webpack 4 and older bundlers) still see `main` and can still resolve subpaths; the refusal is Node's resolver and every bundler that implements it, not a property of the files on disk.
- npm: `checkSpecHash(engineHash)` takes one argument. The pin was a defaulted second parameter on a publicly re-exported function, so `checkSpecHash(h, h)` passed for any `h` and the exported helper read as "compare these two" rather than "compare against the pin". The two-sided comparison is now internal and is not reachable from the package entry point. Callers passing a second argument must drop it; the load-time handshake is unchanged.
- Python `train_test_seeds` raises `ValueError` where it previously used bare `assert` statements, as do the named eval seeds' band and uniqueness guards in `eval_seeds` and the train-seed range check in `dataset.build_dataset`; the sealed-seed band check and the native-versus-Python `EVAL_SEED_BASE` cross-check raise `RuntimeError`. `assert` is removed outright by the CPython compiler under `-O` or `PYTHONOPTIMIZE`, so every one of those guards was absent from a configuration a user can run: `train_test_seeds(256, 256, 0, -256)` lost its range check and its disjointness check together and returned two identical 256-seed bands labelled train and test, over which the generalization gap is zero by construction, which reads as perfect generalization. The `train_test_seeds` docstring said "Disjointness is asserted, not assumed"; it now says what is refused. Callers catching `AssertionError` from these paths must catch `ValueError` or `RuntimeError` instead. `assert_no_regression` already used `raise AssertionError` and is unchanged.

## [0.25.0] - 2026-09-10

### Breaking

- Rust `bootstrap_dsr_ci` and `paired_dsr_diff` return `Result<_, ConfidenceError>` instead of an unconditional report. They require at least two seed units and two resamples, finite usable returns and valid confidence parameters. Paired bands must have equal seed counts and equal per-pair lengths; implicit prefix truncation is removed. Python raises `InvalidArgument` for native refusals and rejects lossy integer-parameter coercion. Baseline tables retain an available point estimate but withhold unsupported intervals with a reason; duplicate seed IDs are refused. These checks do not establish seed independence or empirical interval coverage. See [statistical confidence](docs/statistical-confidence.md).
- Rust `deflated_sharpe`, `bootstrap_dsr_ci` and `paired_dsr_diff` take an explicit `periods_per_year` after `trials_sr_std` instead of converting the annualized prior at a hard-coded 252, and `deflated_sharpe` returns `Result<f64, ConfidenceError>`. `PERIODS_PER_YEAR` (252.0) remains the daily value callers pass. A negative, NaN or infinite `trials_sr_std`, zero trials, or a non-finite or non-positive `periods_per_year` is refused. Previously `deflated_sharpe` turned a negative dispersion (and a NaN one with a single trial) into a zero deflation bar, the most favourable one, which inflated the deflated Sharpe, and returned NaN for a NaN dispersion with more trials; the bootstrap entry points already refused both. A zero dispersion or a single trial still means no deflation. Valid inputs keep their bits. The Python `deflated_sharpe_ci`, `paired_dsr_diff` and `pairwise_significance` and the native bindings gain a `periods_per_year` keyword defaulting to 252.0, as `score_run` does, so no default output moves.

### Added

- Production-linked kernel properties. `crates/sharpearena/tests/kernel_properties.rs` executes the shipped `MarketClearing::reset` / `step` / `is_done`, `clear_bar`, `OrderBook::process_limit` / `process_market` / `step` / `uncross` and `VecTradingEnv::reset_batch` / `step_batch` over seeded SplitMix64 cases (64 per property, no new dependency): reset after any number of steps reproduces a fresh market byte-for-byte and is idempotent; equal inputs clear identically and advance the cursor by one bar; a terminal market stays terminal and clamps its mid, while `NextStep` autoreset yields a fresh first observation; limit-order-book fills conserve depth per side and level, stay inside the crossing range, and honor FIFO and price priority; and per agent per bar, cash, shares, NAV and reward satisfy the kernel's accounting identities exactly. `crates/sharpearena-py/tests/test_lob_accounting_properties.py` checks the Python LOB environment's equity, reward and cross-agent inventory/cash conservation after every seeded step, and pins the repaired seeded-reset baseline. ### Fixed
- transport: a masked hold is a failed cell, never a return series. The external transports cannot signal an error through the `Agent` trait, so a wire fault returned an empty-orders hold and recorded the fault into a `TransportHealth`. Against the native engine an empty-orders decision is a **true hold**: the position persists. A wedged agent therefore rode its last position for the rest of the window, the run completed, and it yielded a return series indistinguishable from a deliberately conservative agent's. The health record was the only mitigation, and the crate re-exported neither `TransportDiagnostics` nor `TransportHealth`, so no consumer could name the type, let alone read it; a repository-wide search found zero readers. `transport_gate` is the reader: `run_backtest_checked` runs an external agent and converts any recorded fault into a typed failed `CellOutcome`, and the diagnostics types are re-exported alongside the transports they describe.
